The question

TabFM already learns in context, so what does training add?

TabFM predicts a row from labelled context rows in one forward pass, with no training step. Fine-tuning keeps that interface and trains it on your table.

Last time: glukicov/ltm

Zero-shot TabFM matched a trained CatBoost model on penguins and on synthetic runners, without training, tuning or a model file.

The paper: arXiv 2506.08982

Full fine-tuning makes TabPFNv2 state of the art on academic benchmarks; on small datasets the gains are often statistically insignificant.

The recipe

The training step calls the unmodified model

src/ltm_ft/finetune.py
loss = episode_loss(model, episode)
loss.backward()  # type: ignore[no-untyped-call]
master.gradients_to_masters()
torch.nn.utils.clip_grad_norm_(master.masters, config.grad_clip)
optimizer.step()
scheduler.step()
optimizer.zero_grad(set_to_none=True)
master.masters_to_params()

No custom forward: frozen parameters do not require gradients, so autograd records nothing until the first trainable block.

Master weights: gradients move to float32 copies, AdamW updates those, and the rounded values go back into the bf16 model.

The laptop problem

1.64B parameters do not fit AdamW in 24 GB; 277M do

What is trainedTrainableOutcome on a 24 GB M4
Everything1.64B~26 GB for weights, gradients and two Adam moments: does not fit
Last 4 of 24 ICL blocks + head277M~10 GB peak, 15–30 s per step used
… + row/column encoders297MBackward through all 24 blocks: 249 s per step, swapping

1.62B of the 1.64B parameters sit in the in-context-learning transformer. The paper found partial fine-tuning close to full fine-tuning.

Round 2 · a table TabFM is bad at

The checkerboard leaves zero-shot TabFM 26 points below the ceiling

Ten uniform features. The label depends only on which square of a 6×6 board the first two fall in: P(yes) is sigmoid(+3) on white squares, sigmoid(−3) on black.

Why it is hard

Neither feature is informative alone, and a row's nearest neighbours in ten dimensions are mostly on other squares.

The gap

Test accuracy: zero-shot 69.1%, ceiling 94.9%. Log loss: 0.614 vs 0.202.

The trap

The same checkpoint computed in float32 loses 11 AUC points

Checkerboard, zero-shot, 500 validation rowsLog lossROC AUCAccuracy
bfloat16 (library default)0.60770.774970.2%
float32 (dtype=None)0.64950.665859.8%

Why it matters: "upcast the weights you train to float32" is the textbook move. Here it changes the model before the first gradient step, and a run could "improve" from 60% back to 70% without learning anything.

The fix

Keep the model in bf16 and the optimiser's copies in float32

src/ltm_ft/finetune.py · class Float32Master
def __init__(self, params: list[nn.Parameter]) -> None:
    self.params = params
    self.masters = [p.detach().float().clone() for p in params]

def gradients_to_masters(self) -> None:
    for p, m in zip(self.params, self.masters, strict=True):
        m.grad = None if p.grad is None else p.grad.float()
        p.grad = None

@torch.no_grad()
def masters_to_params(self) -> None:
    for p, m in zip(self.params, self.masters, strict=True):
        p.copy_(m)

Step 0 is the stock model: a test asserts the prepared model's predictions equal the untouched checkpoint's.

Nothing to convert: the fine-tuned result is a plain bf16 TabFM the stock TabFMClassifier uses directly.

Honest limits

Read these effects as a floor, not a ceiling

Scale
One seed and split per task, 1,500 training rows, 17% of the model, at most 150 steps. The paper trains the whole model on an 80 GB GPU on datasets averaging ~15k rows.
Task choice
The checkerboard was picked because zero-shot TabFM is weak on it. On the realistic table, fine-tuning found nothing.
Decisions
Probabilities and ranking improved; accuracy at the 0.5 threshold did not, within noise.
Licence
TabFM weights are non-commercial, so fine-tuned weights are never committed. Code is MIT. non-commercial weights
Closing

Takeaways and try it

What we found

  • Check the headroom before fine-tuning: a known ceiling makes it measurable
  • Fine-tuning helps where in-context learning struggles, a little on a laptop
  • Assert that step 0 is the model you started with: precision is part of the model
